# AI Challenge: Классификация дефектов 3D-сеток и оценка качества (SOTA Pipeline)

Мультимодальное ML-решение для классификации дефектов и оценки топологического качества 3D-полигональных моделей в рамках чемпионата AI Challenge.

Решение обеспечивает соревновательный скор **12.0+** и **Macro F1 > 0.835** на тестовой выборке за счет синергии визуальных эмбеддингов DINOv2 ViT-L/14, геометрических дескрипторов Trimesh и ансамбля из 55 моделей LightGBM с индивидуальным подбором порогов классификации.

---

## 1. Постановка задачи

По входным 3D-моделям необходимо предсказать:
1. **Качество модели (`quality`):** бинарная метрика общей пригодности сетки.
2. **10 типов визуальных и топологических дефектов:**
   - `abstract`, `artifacts`, `intersection`, `lowpoly`, `noisy`, `open`, `partial`, `scale`, `set`, `simple`.

Целевая соревновательная метрика:
$$\text{Score} = 10 \cdot F_1(\text{quality}) + 10 \cdot F_{1,\text{weighted}}(10 \text{ дефектов})$$

---

## 2. Архитектура и этапы решения

### А. Мультимодальный Feature Engineering (1035 признаков на объект)
- **Глубокие визуальные эмбеддинги (1024 признака):** рендеринг многоракурсных проекций 3D-сетки и прогон через `facebook/dinov2-large` (ViT-L/14). Извлекает визуальные дефекты текстуры, артефакты геометрии и шум.
- **Топологические и геометрические признаки (11 признаков):** расчет характеристик через `trimesh`:
  - Проверка водонепроницаемости сетки (`is_watertight`, `is_winding_consistent`).
  - Углы смежности полигонов (среднее, дисперсия, асимметрия).
  - Соотношение габаритов Bounding Box и объемов выпуклой оболочки (Convex Hull).
  - Количество связных компонент (`n_components`).

### Б. Борьба с сильным дисбалансом классов
- Для редких дефектов (например, `artifacts` с долей 1.19% в датасете) применен адаптивный оверсемплинг **SMOTE**, ограниченный геометрическим пространством признаков для предотвращения искажения эмбеддингов.

### В. Ансамбль из 55 градиентных бустингов (LightGBM)
- **5-Fold Stratified Cross-Validation:** 11 целевых меток $\times$ 5 фолдов = **55 независимых моделей LightGBM**.
- **Калибровка порогов (Threshold Tuning):** вероятностные пороги отсечения подбирались оптимизатором индивидуально под каждый класс для максимизации метрики $F_1$, вместо стандартного порога 0.5.

## 3. Динамика качества моделей

| Итерация | Архитектура / Подход | Ключевые изменения | Соревновательный скор |
| :--- | :--- | :--- | :--- |
| Бейслайн | Single LightGBM | Базовые геометрические фичи | 7.39 |
| Итерация 1 | Обогащение признаков | Добавление эмбеддингов DINOv2 | 9.89 |
| Итерация 2 | Tabular MLP на PyTorch | 512 $\to$ 256 $\to$ 11 с BatchNorm и Dropout | 10.47 |
| **Финальный SOTA** | **Ансамбль 55 LightGBM** | **DINOv2 + Trimesh (1035 фичей) + SMOTE + Threshold Tuning** | **12.0+ (Macro F1 > 0.835)** |

## 5. Интерпретируемость решения

Анализ важности признаков (Feature Importance по gain в LightGBM) подтвердил четкое разделение ролей:
- **Геометрические фичи** отвечают за топологические дефекты (`open`, `intersection`, `lowpoly`, `scale`).
- **DINOv2 эмбеддинги** фиксируют поверхностные аномалии (`noisy`, `artifacts`, `abstract`).
